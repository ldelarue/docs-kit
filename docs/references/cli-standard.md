## The contract (read this first)

1. `cli/<bin>.usage.kdl` is **generated from your CLI code** — never
   hand-edited. It is committed so every PR diff shows interface changes, and
   so completions/man pages/render can run without building the app.
2. `cli/<bin>.usage.extra.kdl` (optional, hand-written) carries what the code
   cannot express: environment settings (`config`), per-command exit codes
   (`exit_code`), output formats and `select` bindings, curated `example`s.
   The generator splices it in; `docs:check` proves core + extras are
   byte-consistent with code after every run.
3. `usage lint` validates the merged spec (names, output/select consistency)
   on every `docs:refresh`; a lint error is a broken contract, not a warning.
4. Regeneration is deterministic. CI's `mise run docs:check` runs the
   regenerate commands and fails on any `git diff` — the page a reader sees
   was rendered from code that exists.

## Defining the CLI so it stays 100 % compatible

Enforced mechanically by this pipeline (fix or CI says so):

- **Flag/arg names, help, defaults, choices come from code.** Typer: every
  `typer.Option` carries non-empty `help=` (it renders verbatim); cobra:
  every flag sets `.Usage`. A flag nobody can name and describe fails review,
  the same as code without tests.
- **Enums, not string comparisons.** Choices are `Enum`/`kdl choices`, so
  `choices` reach the spec, validation, and docs in one move — a free-text
  option whose help says `activity|name` is a drift lie waiting to happen.
- **Exit codes are declared.** If the code raises `typer.Exit(n)` /
  non-zero returns, the merged spec must declare `exit_code n "who knows why"`
  (clig: distinguishable exit codes) — put them in the extra file.
- **CLI-wide config is documented.** Settings read from env (`STASH_TOKEN`,
  pydantic-settings, `env` bindings) exist only inside your process — declare
  them in the extra's `config` block (`prop "jobs" type="uint" default=0 help=
  "..." { env "MYCLI_JOBS" }`), with a `default` and units in the help.
- **Output formats are `output` + `select`.** When a CLI writes structured
  data (clig: stdout is data), declare each format with its media type on the
  selecting flag: `usage lint` refuses an output set whose values disagree
  with the flag's choices. A `table|plain|json|auto` flag must declare all
  four outputs — yes, `auto` too, as `default=#true`, since that is the value
  users actually pass; "auto" resolves to table on a tty / plain when piped,
  documented in its help line.

Judgement calls — clig.dev owns these; the generator cannot see them
(revise them when the rules change):

- **Noun-first command tree, ≤ 2 levels** (`zimbra-versions check`,
  `list units`), verbs only under a group; global behaviour via known flags
  (`--json`, `--quiet`, `--version`).
- **`--help` everywhere**, short+long flags on anything typed by humans;
  stdout = data, stderr = messages; `--version` and `NO_COLOR`.
- **Destructive commands confirm**, or refuse without `--yes`; scope guards
  document their threshold (`exit_code 3 "guard refused"` is that doc).
- **Defaults predictable, config discoverable**: env/config-file/flag
  precedence stated in help or here.

## Per-language recipes (regeneration wiring)

### `docs-kit` — Python / Typer

```toml
# mise.toml — regenerate the committed contract
[tasks."cli:spec"]
description = "Regenerate cli/docs-kit.usage.kdl from the Typer app"
run = 'uv run python "$DOCS_KIT/shared/mise/usage-spec.py" --typer docs_kit.cli:app --bin docs-kit --extra cli/docs-kit.usage.extra.kdl --out cli/docs-kit.usage.kdl'
```


## What the page in `docs/references/cli/` gives your users

Generated by `usage generate markdown` — usage, flags with `-short`/`--long`
and choices, subcommand trees, output formats, exit statuses and the
configuration table. Do not hand-edit the pages: edit the code, run
`mise run docs:refresh`, commit both diff halves.

Extras you get free once `usage` is on PATH:

```sh
usage generate manpage -f cli/<bin>.usage.kdl            # manual page
usage generate completion zsh -f cli/<bin>.usage.kdl     # tab completion
usage g zsh --command <bin> --usage-cmd '<bin> --usage-spec'  # always-fresh completions (go CLIs)
```
